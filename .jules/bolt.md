## 2024-05-14 - Optimize CVXPY canonicalization
**Learning:** For CVXPY, `cp.sum(cp.multiply(A, B))` can be efficiently replaced with the dot product `A @ B` (or `A.T @ B` depending on shapes). This drastically reduces canonicalization time without degrading solver execution time by shrinking the compiled expression tree. Wait, `cp.sum_squares(cp.multiply(W, B))` canonicalizes efficiently to a single highly efficient constraint, whereas `cp.square` introduces element-wise constraints that degrade actual solver time and can even cause memory/allocation errors.
**Action:** Replace `cp.sum(cp.multiply(weights, norms))` with `weights @ norms` for vector norms, and `cp.norm1(cp.multiply(W, B))` with `cp.sum(W.T @ cp.abs(B))` ? But wait, in CVXPY `cp.norm1(cp.multiply(W, B))` and `cp.sum(W.T @ cp.abs(B))` are not strictly equivalent if B has negative values, wait norm1 is sum of absolute values, so `sum(abs(W*B))` is `sum(abs(W)*abs(B))` and since W is positive weights, `sum(W * abs(B))` is valid and equal.
Wait, memory explicitly states: "To optimize CVXPY canonicalization time for weighted norms, you can replace element-wise multiplications with vector inner products (e.g., `cp.norm1(cp.multiply(W, B))` -> `cp.sum(W.T @ cp.abs(B))`). However, DO NOT replace `cp.sum_squares(cp.multiply(W, B))` with `cp.sum((W**2).T @ cp.square(B))`; `cp.sum_squares` canonicalizes to a single highly efficient constraint, whereas `cp.square` introduces element-wise constraints that drastically increase actual solver time."
Also memory states: "For CVXPY performance optimization, replacing element-wise multiplications followed by summation (`cp.sum(cp.multiply(A, B))`) with a vector inner product (`A @ B`) drastically reduces canonicalization time without degrading solver execution time by heavily shrinking the compiled expression tree."
