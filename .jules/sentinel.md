## 2024-05-01 - [CVXPY canonicalization backend injection]
**Vulnerability:** The `canon_backend` parameter in `Regressor` was directly passed to the underlying `cvxpy.Problem.solve` without validation. While CVXPY implements some internal checks, a bare `try-except` block mapping standard Python `Exception`s or `ValueError`s can swallow unexpected errors from deeper levels (like missing backends or unsafe imports dynamically loaded by a backend), obscuring the root cause and potentially allowing unintended execution paths or denial of service if bad input is repeatedly provided.
**Learning:** Even though hyperparameter validation in local ML wrappers does not typically constitute a severe remote injection vulnerability, it is a crucial defense-in-depth practice. Unvalidated string inputs passed to complex dependencies (like solver backends) can trigger internal exceptions that are poorly handled, creating operational vulnerabilities or unexpected test/runtime failures.
**Prevention:** Implement explicit allowlists (e.g., `ALLOWED_CANON_BACKENDS = {"CPP", "SCIPY", "COO"}`) and validate string parameters strictly at the wrapper boundary (`_check_attributes`) before they interact with internal dependencies.
## 2024-05-02 - [Input Validation for Numeric Types]
**Vulnerability:** Scikit-learn's `check_scalar` was previously called with `target_type=(int, float)` in `BaseModel` for attributes like `lambda1`. This fails to correctly validate NumPy numeric types like `np.float64` and incorrectly validates them as invalid if checking strictly against Python `int` or `float`. Furthermore, `AdaptiveWeights` did not strictly validate `weight_tol` or `variability_pct` using `check_scalar`, which could lead to domain errors (e.g., division by zero if `weight_tol=0.0` or `<0.0`, or incorrect slicing behavior for invalid `variability_pct`).
**Learning:** For broad numerical compatibility across different environments (especially when users pass arrays or dataframes mapped from NumPy), `target_type=numbers.Real` should be used instead of `target_type=(int, float)` when using `check_scalar`. Missing explicit scalar bounds validation on critical hyperparameters can lead to deeper domain errors.
**Prevention:** Always use `numbers.Real` for floating point or numerical validations via scikit-learn's `check_scalar`. Ensure all numerical hyperparameters used in deeper logical checks/calculations (like `weight_tol` and `variability_pct` in `AdaptiveWeights`) have boundaries validated strictly and as early as possible.
