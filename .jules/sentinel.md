## 2024-05-01 - [CVXPY canonicalization backend injection]
**Vulnerability:** The `canon_backend` parameter in `Regressor` was directly passed to the underlying `cvxpy.Problem.solve` without validation. While CVXPY implements some internal checks, a bare `try-except` block mapping standard Python `Exception`s or `ValueError`s can swallow unexpected errors from deeper levels (like missing backends or unsafe imports dynamically loaded by a backend), obscuring the root cause and potentially allowing unintended execution paths or denial of service if bad input is repeatedly provided.
**Learning:** Even though hyperparameter validation in local ML wrappers does not typically constitute a severe remote injection vulnerability, it is a crucial defense-in-depth practice. Unvalidated string inputs passed to complex dependencies (like solver backends) can trigger internal exceptions that are poorly handled, creating operational vulnerabilities or unexpected test/runtime failures.
**Prevention:** Implement explicit allowlists (e.g., `ALLOWED_CANON_BACKENDS = {"CPP", "SCIPY", "COO"}`) and validate string parameters strictly at the wrapper boundary (`_check_attributes`) before they interact with internal dependencies.

## 2024-05-23 - [Logistic Regression Target Validation Bypass]
**Vulnerability:** The input validation logic for logistic regression targets used a flawed condition: `if type_of_target(y) != "binary":`. This completely bypassed explicit checks if an array evaluating to "binary" via scikit-learn (e.g. `y = [-1, 1]`) was provided. Additionally, the subsequent explicit `{0, 1}` checks incorrectly used a bitwise OR (`|`) instead of logical `and`, mathematically enforcing that even correct inputs failed validation once inside the block.
**Learning:** Validations reliant on external library utility functions (like `type_of_target`) can be dangerously opaque and unexpectedly loose. A target with `[-1, 1]` is valid mathematically as a binary array, but is destructive if the internal math uniquely assumes `{0, 1}` operations. Furthermore, chaining logical boolean expressions with bitwise operators across variables creates subtle, devastating logic flaws where validation is trivially bypassed or impossible to pass.
**Prevention:** Remove overly permissive external heuristics in security-critical validation paths. Enforce explicit, hardcoded mathematical checks on untrusted arrays, and ensure boolean logic operations exclusively use logical keywords (`and`, `or`) rather than bitwise proxies.
